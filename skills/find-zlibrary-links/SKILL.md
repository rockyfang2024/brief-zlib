# 查找可用的 Z-Library 地址

目标：给出有来源、有当前访问证据的入口。本项目将“到达 Z-Library 首页或站点的浏览器验证页”均视为入口可用；不要求通过验证、登录或下载书籍。可用表示入口可达，不保证后续功能可用。需要更新文档时，沿用现有格式。

## 快速查找

1. 优先检查用户给定网址和目标 README 已有的网址。已有地址可用且满足数量要求时，不必继续广泛搜索。
2. 从 GitHub 项目获取候选链接。以下是发现线索，不是永久有效地址清单：
   - https://github.com/dongyubin/Awesome-Zlibrary
   - https://github.com/runningcheese/Awesome-Zlibrary
   - https://github.com/heartleo/zlib （README 中的域名检测、HTML 与 EAPI 差异说明）
   - https://github.com/z-libraryopp/z-libraryopp.github.io
3. 需要扩展时，查询 GitHub 仓库搜索 `zlibrary` 或 `Z-Library`，按 Star 排序，再结合最近更新内容筛选。可用公开 API：`https://api.github.com/search/repositories?q=zlibrary&sort=stars&order=desc&per_page=10`。Star 只能辅助筛选，不能证明域名真实或仍可用。
4. 阅读当前 README，必要时查看维护者最近的提交或 Issue；记录仓库来源和提取日期。去重候选地址，优先测试最近维护的入口。排除推广、网盘、代理服务、地址导航页及其他图书馆；它们可以提供线索，但不是 Z-Library 首页。
5. 初轮测试约 5–10 个高可信候选；有足够可用入口后停止。若全部受阻，再扩展一轮来源，避免反复扫描大量历史域名。

保留不同入口域名，即使它们跳转到同一个首页；记录最终域名用于说明。仓库称“官方”并不能独立证明官方身份，不给未经核实的镜像贴官方标签。

## 连通性与页面验证

先用 HTTP GET 获取 HTML 并跟随重定向，保存状态码、最终 URL、耗时及页面标题。不要仅用 HEAD 或仅看状态码。

以下命令用于单次直连测试。把 `URL` 替换为实际提取的地址，输出放入临时目录，不放进项目。使用独立文件名保存不同候选的结果。

```sh
curl --silent --show-error --location --max-redirs 5 \
  --connect-timeout 10 --max-time 30 --compressed \
  --proxy '' --noproxy '*' \
  --output /tmp/zlibrary-home.html \
  --write-out 'status=%{http_code}\nfinal=%{url_effective}\nhtml_seconds=%{time_total}\n' \
  'URL'
```

需要代理对照且已有可用代理时，将 `--proxy '' --noproxy '*'` 替换为 `--proxy 'PROXY_URL' --noproxy ''`，使用当前环境实际提供的代理地址，不硬编码端口。不修改用户系统网络设置，不输出代理凭据。

判断返回内容：

| 证据 | 结论与后续处理 |
| --- | --- |
| 展示图书馆首页，含搜索框、书目或明确的图书馆导航 | 首页可用；不等于登录、搜索、下载均已测试 |
| 用户明确确认该地址能到达首页 | 可收录，注明人工确认；不要声称 AI 已完成首页验证 |
| 返回站点浏览器验证页，如 “Checking your browser” 或自动计算验证页（可能为 HTTP 503） | 按本项目标准视为入口可用，可收录并更新可用时间；注明“到达验证页”，不声称首页已加载 |
| 仅返回 503 等错误码，没有可识别的站点验证内容 | 不视为可用；报告具体错误或待确认 |
| 200 但实际为域名停放、出售、广告、空白跳转页 | 不收录 |
| 只有 EAPI 可响应，HTML 首页未验证 | 不作为已验证的网页入口；可在说明中单独报告 |
| DNS、TLS、连接重置、超时、重定向循环 | 本次路径失败；不能据此断言全球失效或一定需要代理 |

遇到自动验证页时，核对来源域名、最终跳转地址和页面内容，排除代理错误页、停放页和无关跳转。确认是站点验证页后即可结束可用性检查，无需额外通过验证。只有用户要求进一步检查首页时，才使用浏览器正常打开并读取内容或截图；浏览器工具失败不撤销已经确认的验证页可达结果。

不要把手工构造验证令牌、破解验证码或绕过浏览器安全警告当作测速步骤。遇到审批拒绝时停止被拒操作，不换工具间接执行。不得为验证入口要求用户提供密码，也无需登录账户。

## 是否需要魔法网络

- 有明确的用户实测结论时，按其结论填写，并在交付说明中说明来源；保留已有人工结论，除非有新证据或用户要求复测。
- 同一环境下，直连到达首页或站点验证页：填写“否（本次网络）”。直连失败而代理到达首页或站点验证页：填写“是（本次网络）”。这描述入口可达所需的网络，不保证验证后功能正常。
- 仅测试了代理且成功、未完成直连对照，或两种路径均失败：填写“未确认”，不要猜测是或否。验证页响应本身是有效的可达证据。
- `curl` 禁用显式代理仍可能经过 VPN、TUN 或路由器代理。检查已有代理及路由信息；无法排除透明代理时，说明测试路径不确定。不能把境外机器的直连成功等同于中国大陆直连成功。
- 区域和运营商不同可能有不同结果，不把单点测试写成全国性保证。

## 速度与时间

- 对准备收录的入口，在成功路径上顺序测量 3 次，取中位数，注明直连或代理。保留成功次数；有失败时说明波动。若只测一次，明确“单次”。
- `curl time_total` 是获取 HTML 的耗时，包含跟随重定向的时间，不是浏览器完整加载时间或下载速度。访问速度列使用“直连 HTML 1.2 秒（3 次中位数）”等可解释描述。
- 工具取得站点验证页时，其响应耗时可用于访问速度，但必须明确标注“至验证页，非首页完整加载”。不使用其他错误页或失败请求耗时表示访问速度。
- “最新可用时间”使用本次实际到达首页或站点验证页的时间与用户时区；到达验证页也应更新，不保留更早的首页确认日期作为最新可用时间。人工确认只有日期时只写日期，不补造精确时间。仅复用历史证据时保留历史日期。

## 输出与文档更新

仅将按上述标准确认可用的地址放入最终表格，包括已到达站点验证页的入口。证据不足或失败的候选放在聊天说明中，不混入“可用”表；一个也无法确认时，直说未确认，不捏造结果。

```markdown
| 网站地址 | 是否需要魔法网络 | 访问速度 | 最新可用时间 |
| --- | --- | --- | --- |
```

保留用户已有的标题、简介及人工修正。向用户简述本次来源、验证范围以及尚未确认的限制，来源链接不必强行添加为新表格列。

只有用户要求更新文件时才修改文档；提交或推送按用户授权执行。发布前检查差异，只提交相关文件，不包含临时 HTML、测速日志、Cookie 或凭据。GitHub 凭据不可用时保留本地成果，明确“未推送”，不要声称已经上传。
